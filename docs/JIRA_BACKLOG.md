## Legend

- **Type**: `Bug` (defect), `Story` (user-facing feature), `Task` (engineering work), `Improvement` (refactor/UX), `Test` (test case), `Sec` (security), `Doc` (documentation), `Sub-task` (small unit of larger work).
- **Priority**: `Highest`, `High`, `Medium`, `Low`. Aligns with JIRA's default scheme.
- **Status**: `To Do` (open), `In Progress`, `Done` (already completed in this codebase).
- Tickets marked **Done** are bugs/features already resolved during this development — kept in the backlog as historical reference.

## How to use this backlog

1. Bulk-import into JIRA via CSV (re-export the tables to CSV format).
2. Filter by epic / type / priority to scope sprint planning.
3. Sub-tasks are placeholders for granular work — size and detail before pickup.
4. "Done" items show what's already in production — useful for retrospectives.
