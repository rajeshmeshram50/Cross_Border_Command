## 1. OVERVIEW

The **Roles** master (`roles`) defines the named job roles (Admin, HR, Approver, Accountant, …) used to describe a user's function and grouping. Each role carries an auto-generated `ROL-##` code and may be linked to a department and a role category. It is a schema-driven master served by `MasterController` + `MasterPage.tsx`.

**Downstream consumers:** roles are referenced by the **KPI Master** (each KPI is assigned to a role) and by HR/employee role assignment. Role is a descriptive/classification master here; module access permissions are managed separately in the Permission system.

---

## 2. ROLES & ACCESS

Permissioned module `master.roles` (`can_view / can_add / can_edit / can_delete`). Super admin bypasses.

| Role | Visibility |
|---|---|
| Super Admin | All rows, all tenants; may seed globals |
| Client Admin / Client User | Own client's rows + globals; branch-switcher narrows |
| Branch User | Globals + client-level + own branch rows |
| Employee | Globals + client-level + only own rows |

## 4. BUSINESS RULES

- **Uniqueness (`uFields` = [name]):** single text field → promoted to a **case-insensitive** unique check within the tenant scope, so "Admin" and "admin" collide.
- **Auto-code (`ROL-##`):** generated by the model's `creating` hook when `code` is blank — `ROL-` + zero-padded `max(id)+1`. *(Note: based on the global table `id`, not a per-tenant sequence; and it is not wired to the generic `next-code` endpoint, which returns `null` for this slug.)*
- **No uploads, no sublist, no system-seed, no cascade filter.** Empty strings → NULL.

---

## 5. SCREEN

Lives under Masters → **Roles** (`/masters/roles`). Add/Edit modal shows the Role Code as auto-generated (read-only hint), Department and Role Category dropdowns, and a description textarea. List columns: Code, Role Name, Role Type, Department, Category, Status.

---

## 6. KNOWN LIMITATIONS

- `code` auto-number uses `max(id)+1` globally, so ROL codes are not per-tenant sequential and can appear to "skip" as other tenants insert rows.
- The generic `/master/roles/next-code` returns `null` (the code is assigned by the model hook at save time, not pre-fetched).
- Delete has no in-use guard against KPIs/employees referencing the role.
