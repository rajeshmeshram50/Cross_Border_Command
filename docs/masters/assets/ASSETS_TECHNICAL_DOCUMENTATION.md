## 1. Model & Table

- **Model:** `App\Models\Masters\Assets`
- **Table:** `master_assets` (PostgreSQL, SoftDeletes)
- **Slug:** `assets` (registered in `MasterController::MODELS`)
- **File-path columns:** `invoice_file_path`, `warranty_card_file_path` (populated by the upload absorber; the raw `*_file` request keys are never mass-assigned).
- **Fillable:** `client_id`, `branch_id`, `asset_name`, `code`, `asset_number`, `asset_type_id`, `description`, `vendor_id`, `purchase_date`, `warranty_expiry_date`, `invoice_file_path`, `warranty_card_file_path`, `assign_date`, `status`, `created_by`.
- **Relations:** `client`, `branch`, `creator` (`created_by`), `vendor` (→ `VendorDirectory` via `vendor_id`).
- **Model hook:** `booted()::creating` auto-fills `code` as `AST-####` when empty.

`uEach` = `['asset_name', 'code']`. File fields (`invoice_file`, `warranty_card_file`) are **not** in the schema — they are handled generically by `absorbUploads()`.

## 3. Uniqueness Model

- `uEach` → each of `asset_name` and `code` validated independently.
- Text fields compared case-insensitively (`LOWER`); scoped to the row's `(client_id, branch_id)` tuple resolved from the caller (`resolveOwnership`), so each tenant keeps its own `AST-` series and name space.

## 5. Special Handling

- **Uploads (`absorbUploads`)** — for each uploaded `*_file` key, the target column is `*_file_path`; only applied if that column is fillable. File is `store('master/assets','public')`; on update the old file is deleted first. Applies to `invoice_file` → `invoice_file_path`, `warranty_card_file` → `warranty_card_file_path`.
- **Auto code** — generated by the **model's `creating` hook** (`AST-####`), not by the `AUTO_CODES` next-code endpoint. `next-code` therefore returns `{code:null}`; the frontend computes its own preview from the loaded list.
- **References** — `asset_type_id` and `vendor_id` are validated as integers; their target rows must be within the caller's read scope.

## 6. Security & Scoping

- Every op runs behind `auth:sanctum` + `user.active` and `authorizeMaster('master.assets', …)`; super admin bypasses.
- Reads scoped by `MasterVisibility::applyReadScope` (globals + own client/branch); writes stamp `client_id`/`branch_id`/`created_by` from the authenticated user (body `client_id` never trusted for non-super).
- Edit/delete pass `hierarchicalDenial`; `is_system` rows (none seeded here by default) would be edit-locked.

## 7. Metrics

- Response shape: bare JSON array (list) / object (item), ownership names flattened (`client_name`, `branch_name`, `creator_name`), `orderByDesc('id')`.
- Every write calls `MasterBundleCache::bump()` so dropdowns refresh.
