## 1. OVERVIEW

The **Designations** master (`designations`) defines job titles (CEO, HR Manager, Senior Software Engineer, …), their organizational level, department and reporting line. Each designation carries an auto-generated `DGN-##` code. It is a schema-driven master served by `MasterController` + `MasterPage.tsx`.

**Downstream consumers:** designations appear on offer/appointment letters, employee profiles and HR records; the self-referential `reports_to_id` builds the reporting hierarchy, and `level` classifies seniority.

---

## 2. ROLES & ACCESS

Permissioned module `master.designations` (`can_view / can_add / can_edit / can_delete`). Super admin bypasses.

| Role | Visibility |
|---|---|
| Super Admin | All rows, all tenants; may seed globals |
| Client Admin / Client User | Own client's rows + globals; branch-switcher narrows |
| Branch User | Globals + client-level + own branch rows |
| Employee | Globals + client-level + only own rows |

---

## 4. BUSINESS RULES

- **Uniqueness (`uFields` = [name]):** single text field → **case-insensitive** unique check within the tenant scope. *(The frontend config also lists `code`, but the backend enforces uniqueness on `name` only.)*
- **Auto-code (`DGN-##`):** generated by the model's `creating` hook when `code` is blank — `DGN-` + zero-padded `max(id)+1` (2-pad, grows past 99). Based on the global table `id`, not a per-tenant sequence; not wired to `next-code` (returns null).
- **Self-reference:** `reports_to_id` points to another designation, resolved in the dropdown as `{name} ({level})`.
- **No uploads, no sublist, no system-seed, no cascade filter.** Empty strings → NULL.

---

## 5. SCREEN

Lives under Masters → **Designations** (`/masters/designations`). Add/Edit modal shows the Code as auto-generated, Department + Level dropdowns and a Reports-To picker. List columns: Code, Designation Name, Status.

---

## 6. KNOWN LIMITATIONS

- `code` auto-number uses `max(id)+1` globally, so DGN codes are not per-tenant sequential.
- No cycle-prevention on `reports_to_id`.
- Delete has no in-use guard against employees referencing the designation.
